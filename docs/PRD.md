# Unreal Hub 기획서 (PRD)

- 문서 버전: v0.1 (인터뷰 기반 초안)
- 작성일: 2026-11-16
- 대상 플랫폼: Windows (1차), 구조는 크로스플랫폼을 고려
- 기술 스택: Rust + GPUI
- 대상 엔진 버전: UE 5.6 ~ 5.9 (검증·지원 기준). 5.6 미만 엔진도 감지·열기는 되지만 검증 대상은 아님

---

## 1. 개요

### 1.1 한 줄 정의
Unreal Hub는 **엔진 버전 관리와 프로젝트 열기**에만 집중한, Zed 수준으로 빠르고 가벼운 언리얼 엔진 런처다. 레이아웃과 사용 흐름은 Unity Hub를 거의 그대로 따른다.

### 1.2 만드는 이유
- Epic Games Launcher는 무겁고 느리며, 스토어·뉴스·마켓플레이스 등 프로젝트 작업과 무관한 요소가 많다.
- 엔진 버전이 여러 개(런처 설치, 소스 빌드, 사내 빌드)일 때 프로젝트와 엔진의 매칭을 한눈에 보기 어렵다.
- Unity Hub처럼 "프로젝트 목록 → 클릭 → 에디터 실행"이라는 단순한 흐름이 필요하다.

### 1.3 목표
| 구분 | 목표 |
|---|---|
| 속도 | 앱을 켜는 즉시 프로젝트를 클릭할 수 있어야 한다 (콜드 스타트 300ms 이내 첫 프레임) |
| 단순함 | 좌측 탭은 **프로젝트**, **설치** 두 개뿐 |
| 정확성 | PC에 있는 엔진을 자동으로 찾고, 각 프로젝트가 어떤 엔진을 쓰는지 정확히 보여준다 |
| 안전성 | 파일을 지우거나 `.uproject`를 고치는 작업은 항상 확인을 거치고, 가능하면 되돌릴 수 있게 한다 |

### 1.4 범위 밖 (Non-goals)
- 템플릿 탭, 학습/뉴스/받은편지함/알림/계정 로그인
- 엔진 **다운로드/설치** 자체 (Epic Launcher 또는 사용자가 직접 수행, Hub는 감지·등록만 함)
- 마켓플레이스/Fab, 플러그인 관리
- 빌드·패키징, VCS(Git/Perforce) 연동, IDE 솔루션 열기
- 프로젝트 상세 화면, 엔진 상세 화면
- macOS/Linux 지원 (1차 버전 기준)

## 2. 성능·반응성 요구사항

| 항목 | 목표치 |
|---|---|
| 콜드 스타트 (exe 실행 → 첫 프레임) | < 300ms |
| 프로젝트 목록 첫 표시 | 캐시된 목록 기준 첫 프레임에 함께 표시 |
| 탭 전환 | 즉시 (다음 프레임) |
| 검색 필터링 | 입력 후 1프레임(16ms) 이내 반영, 프로젝트 1,000개 기준 |
| 스크롤 | 120fps 유지 (가상화 리스트 사용) |
| 유휴 메모리 | < 100MB |
| 유휴 CPU | 0%에 수렴 (폴링 없이 파일 감시 이벤트 기반) |

설계 원칙:
1. **UI 스레드에서 I/O 금지.** 파일 읽기, 레지스트리 조회, 폴더 용량 계산, 디렉터리 스캔은 모두 GPUI background executor에서 실행하고 결과만 UI 상태에 반영한다.
2. **캐시 우선 표시.** 시작 시 마지막 저장 상태(JSON)를 즉시 그리고, 엔진 감지와 프로젝트 유효성 검사는 백그라운드에서 끝나는 대로 갱신한다.
3. **느린 정보는 지연 계산.** 폴더 용량처럼 오래 걸리는 값은 필요한 화면(캐시 정리 다이얼로그, 설치 목록)이 열릴 때 계산하고, 계산 중에는 스피너를 보여준다.
4. 리스트는 GPUI `uniform_list`로 가상화한다.

## 4. 전역 레이아웃

### 4.1 와이어프레임

```
┌──────────────────────────────────────────────────────────────────────┐
│ [◆] Unreal Hub                                        [⚙]   ─  □  ✕ │ ← 커스텀 타이틀바 (드래그 영역)
├────────────────┬─────────────────────────────────────────────────────┤
│ ┌────────────┐ │ ┌─────────────────────────────────────────────────┐ │
│ │ 📁 프로젝트 │ │ │                                                 │ │
│ │ 🗄 설치     │ │ │               메인 콘텐츠 영역                   │ │
│ └────────────┘ │ │                                                 │ │
│                │ │                                                 │ │
│                │ └─────────────────────────────────────────────────┘ │
├────────────────┴─────────────────────────────────────────────────────┤
│ (업데이트 배너: 새 버전이 있을 때만 메인 영역 상단에 표시)              │
└──────────────────────────────────────────────────────────────────────┘
```

### 4.2 커스텀 타이틀바
| 요소 | 동작 |
|---|---|
| 로고 + "Unreal Hub" | 표시 전용. 영역 드래그 시 창 이동, 더블클릭 시 최대화/복원 |
| ⚙ 설정 아이콘 | 설정 모달 열기 |
| ─ □ ✕ | 최소화 / 최대화·복원 / 닫기. 닫기는 설정 "닫을 때 트레이로"가 켜져 있으면 트레이로 숨김 |

- Windows 11 스냅 레이아웃(최대화 버튼 hover)과 창 가장자리 리사이즈를 지원한다.
- 사이드바 접기 기능은 두지 않는다.

### 4.3 좌측 사이드바
- 항목: **프로젝트**, **설치** (아이콘 + 라벨)
- 선택된 항목은 배경 하이라이트 (스크린샷의 "프로젝트" 행 스타일)
- 앱 재시작 시 마지막으로 보던 탭을 복원한다.
- Unity Hub의 "설정 가져오기", "템플릿"은 넣지 않는다.

### 4.4 창 기본값
- 최소 크기: 900 × 560
- 기본 크기: 1040 × 700
- 마지막 창 위치·크기·최대화 상태를 저장하고 복원한다.

### 4.5 전역 피드백 요소
| 요소 | 사용처 |
|---|---|
| 토스트 (우하단, 4초 후 자동 닫힘) | 작업 완료/실패 알림 (예: "캐시 1.2GB 정리됨", "엔진 실행 실패") |
| 업데이트 배너 | 새 버전 발견 시 메인 영역 상단: "새 버전 v0.3.0이 있습니다 [업데이트] [나중에]" |
| 진행 표시 | 오래 걸리는 작업(프로젝트 생성, 캐시 삭제)은 해당 다이얼로그/행 안에 진행 상태 표시 |

### 4.6 공통 키보드 동작
- `Esc`: 열린 모달/메뉴 닫기
- `Enter`: 모달의 기본 버튼 실행
- `Tab`: 포커스 이동

## 5. 화면 1 — 프로젝트

### 5.1 와이어프레임

```
┌─────────────────────────────────────────────────────────────────────┐
│ 프로젝트                     [🔍 검색        ] [추가 ∨] [+ 새 프로젝트] │
├─────────────────────────────────────────────────────────────────────┤
│  ☆ │ 이름 ▲                                      │ 엔진 버전    │     │
├─────────────────────────────────────────────────────────────────────┤
│  ★ │ MyShooter                                   │ 5.9          │ ⋯  │
│    │ D:\Projects\MyShooter                       │              │     │
│  ☆ │ OldPrototype                       ●실행 중 │ 5.5 ⚠        │ ⋯  │
│    │ D:\Old\OldPrototype                         │              │     │
└─────────────────────────────────────────────────────────────────────┘
```

### 5.2 헤더 영역
| 요소 | 동작 |
|---|---|
| 제목 "프로젝트" | 표시 전용 |
| 검색창 | 이름·경로 대상 실시간 퍼지 검색. 입력 즉시 필터링. 지우기(✕) 버튼 |
| 추가 ∨ | 드롭다운: **디스크에서 프로젝트 추가** (`.uproject` 파일 선택 대화상자) |
| + 새 프로젝트 | 새 프로젝트 다이얼로그 열기 (§5.8) |

### 5.3 목록 열 구성
| 열 | 내용 | 정렬 |
|---|---|---|
| ☆ 즐겨찾기 | 별 아이콘 클릭으로 토글. 즐겨찾기는 정렬과 무관하게 항상 상단 고정 | 헤더 클릭 불가 |
| 이름 | 1행: 프로젝트 이름(`.uproject` 파일명), 2행: 폴더 경로(작은 회색 글씨) | 헤더 클릭으로 오름/내림차순 |
| 엔진 버전 | `EngineAssociation` 해석 결과 (§8.3). 문제 있으면 ⚠ 아이콘 | 헤더 클릭으로 오름/내림차순 (버전 비교) |
| ⋯ | 행 메뉴 버튼 (hover 시 표시) | — |

**기본 정렬:** 즐겨찾기 → Hub에서 마지막으로 연 시간 내림차순 (열에는 표시하지 않는 내부 기준). 헤더를 클릭하면 해당 열 정렬로 바뀌고, 다시 기본 정렬로 돌아가려면 정렬 헤더를 세 번째 클릭한다 (오름 → 내림 → 해제). 정렬 상태는 저장한다.

### 5.4 행 상태
| 상태 | 표시 | 클릭 시 동작 |
|---|---|---|
| 정상 | 기본 | 해당 엔진으로 에디터 실행 |
| 실행 중 (Hub가 실행한 에디터 프로세스가 살아있음) | 이름 옆 "● 실행 중" 배지 | 이미 열린 에디터 창을 앞으로 가져옴. 창을 못 찾으면 "이미 실행 중입니다" 토스트 |
| 엔진 없음 (연결된 엔진이 설치 목록에 없음) | 버전 옆 ⚠, 툴팁 "엔진 5.5가 설치되어 있지 않습니다" | 엔진 없음 다이얼로그 (§5.10) |
| 엔진 내장 프로젝트 (`EngineAssociation` 비어있음, 엔진 트리 내부) | 버전 칸에 상위 엔진 이름 + "(내장)" | 해당 엔진으로 실행 |
| 알 수 없는 빌드 (GUID가 어떤 엔진과도 매칭 안 됨) | 버전 칸 "알 수 없는 빌드" ⚠ | 엔진 없음 다이얼로그 |

### 5.5 프로젝트 열기 (행 클릭)
1. 행을 **한 번 클릭**하면 바로 실행한다 (Unity Hub와 동일). 별 아이콘·⋯ 버튼 클릭은 실행하지 않는다.
2. 실행 명령: `<엔진>\Engine\Binaries\Win64\UnrealEditor.exe "<프로젝트>.uproject"`
3. 실행 직후 행에 "실행 중" 배지를 표시하고, 프로세스 종료를 감지하면 배지를 제거한다.
4. 마지막 연 시간을 갱신한다.
5. Hub는 그대로 유지한다. 단, 설정에서 "에디터 실행 후 Hub 최소화"를 켰다면 최소화한다.
6. 실행 실패(exe 없음, 권한 등) 시 오류 토스트.

### 5.6 행 메뉴 (⋯ 버튼 또는 우클릭)
| 메뉴 | 동작 |
|---|---|
| 탐색기에서 보기 | 프로젝트 폴더를 탐색기로 열고 `.uproject` 선택 |
| 엔진 버전 변경… | 엔진 버전 변경 다이얼로그 (§5.9) |
| 캐시 정리… | 캐시 정리 다이얼로그 (§5.11) |

- "목록에서 제거" 기능은 없다. 목록은 감지 결과 그 자체이며, 감지된 프로젝트는 항상 표시된다 (§5.12).
- "실행 중" 상태에서는 "엔진 버전 변경", "캐시 정리"를 비활성화하고 툴팁으로 이유를 보여준다.

### 5.7 빈 상태
| 상황 | 표시 |
|---|---|
| 프로젝트 0개 | 큐브 아이콘 + "프로젝트 없음" + "시작하려면 새 프로젝트를 생성하거나 프로젝트를 추가하세요." + [프로젝트 추가] [+ 새 프로젝트] (스크린샷과 동일) |
| 검색 결과 없음 | "'검색어'와 일치하는 프로젝트가 없습니다" + [검색 지우기] |

### 5.8 다이얼로그 — 새 프로젝트

```
┌─ 새 프로젝트 ──────────────────────────────────────────────── ✕ ┐

├──────────────────────────────────┬──────────────────────────────┤
│ ┌──────┐ ┌──────┐ ┌──────┐        │ [썸네일 큰 이미지]            │
│ │Blank │ │ FPS  │ │ TPS  │        │ Third Person                 │
│ └──────┘ └──────┘ └──────┘        │ 템플릿 설명 텍스트...         │
│ ┌──────┐ ┌──────┐ ┌──────┐        │                              │
│ │ Top  │ │Vehicle│ │ VR  │        │ 프로젝트 유형  (BP)( C++ )    │
│ └──────┘ └──────┘ └──────┘        │ 타겟 플랫폼  (데스크톱)(모바일)│
│                                   │ 품질 프리셋  (최대)(확장 가능) │
│                                   │ 스타터 콘텐츠        [ ON ]   │
│                                   │ 레이트레이싱         [ OFF ]  │
│                                   │ ───────────────────────────── │
│                                   │ 프로젝트 이름 [MyProject    ] │

```

**입력 항목**
| 항목 | 기본값 | 규칙 |
|---|---|---|
| 엔진 버전 | 설정의 "기본 엔진 버전", 없으면 가장 높은 버전 | 설치 탭에 있는 엔진만 선택 가능 |
| 템플릿 | Blank | 선택한 엔진의 `Engine\..\Templates\TP_*` 폴더를 읽어 그리드로 표시. 썸네일·이름·설명은 각 템플릿의 `Config\TemplateDefs.ini`와 `Media` 폴더에서 가져옴 |
| 프로젝트 유형 | BP | BP/C++ 쌍(`TP_Blank`/`TP_BlankBP` 등)으로 템플릿 폴더를 매핑. 한쪽만 있는 템플릿은 다른 쪽을 비활성화 |
| 타겟 플랫폼 | 데스크톱 | 데스크톱 / 모바일 |
| 품질 프리셋 | 최대 | 최대 / 확장 가능 |
| 스타터 콘텐츠 | ON | |
| 레이트레이싱 | OFF | |
| 프로젝트 이름 | MyProject (중복 시 MyProject1, 2…) | 영문자로 시작, 영문·숫자·`_`만, 20자 이하 (엔진 규칙과 동일) |
| 위치 | 설정의 "새 프로젝트 기본 경로" | 존재하는 폴더여야 함. `<위치>\<이름>` 폴더가 이미 있으면 오류 |
| 생성 후 바로 열기 | ON (마지막 선택 기억) | |

**검증 & 피드백**
- 입력 오류는 해당 필드 아래 빨간 글씨로 즉시 표시하고 [프로젝트 생성] 버튼을 비활성화한다.
- C++ 선택 시 Visual Studio 툴체인이 감지되지 않으면 경고: "C++ 프로젝트를 빌드하려면 Visual Studio가 필요합니다" (생성은 허용).
- 엔진이 하나도 없으면 다이얼로그 대신 "설치된 엔진이 없습니다. 설치 탭에서 엔진을 추가하세요" 안내 + [설치 탭으로 이동].

**생성 절차 (백그라운드)**
1. 템플릿 폴더를 `<위치>\<이름>`으로 복사 (`Binaries`, `Intermediate`, `Saved`, `DerivedDataCache` 제외)
2. `TP_xxx.uproject` → `<이름>.uproject`로 이름 변경, `EngineAssociation`을 선택한 엔진 식별자로 기록
3. C++: 모듈 이름·소스 파일명·`*.Target.cs`·`*.Build.cs`·클래스 API 매크로(`TP_XXX_API`)를 새 이름으로 치환, 이후 `GenerateProjectFiles` 실행
4. 설정 옵션을 `Config\DefaultEngine.ini` / `DefaultGame.ini`에 기록 (하드웨어 타기팅, 레이트레이싱, 스타터 콘텐츠 팩 추가 액션)
5. 프로젝트 목록에 추가하고 "생성 후 바로 열기"가 켜져 있으면 에디터 실행

생성 중에는 다이얼로그 하단에 진행 단계("템플릿 복사 중…", "프로젝트 파일 생성 중…")를 표시하고 [취소]로 중단할 수 있다. 중단·실패 시 만들던 폴더를 정리한다.

> 기술 리스크: 언리얼 에디터 내부(GameProjectUtils)의 생성 로직을 재현하는 방식이라 엔진 버전별 차이가 있을 수 있다. 구현 단계에서 UE 5.6~5.9 템플릿으로 검증한다. (§14 미결 사항 참고)

- 완료 시 "MyShooter 캐시 8.5GB 정리됨" 토스트.

### 5.12 프로젝트 목록 자동 채우기
| 소스 | 시점 | 설명 |
|---|---|---|
| 디스크에서 추가 | 사용자가 "추가 ∨" 사용 | `.uproject` 파일 선택. 이미 있으면 해당 행으로 스크롤·하이라이트 |
| 드래그 앤 드롭 | 창에 `.uproject` 또는 폴더 드롭 | 폴더면 하위를 스캔해 일괄 추가 |
| 감시 폴더 | 앱 시작 시 스캔 + 실행 중 파일 시스템 감시 | 설정 > 프로젝트에서 관리. 하위 3단계까지 `.uproject` 탐색, 새로 생기면 자동 추가 |
| 엔진 최근 프로젝트 | 최초 실행 시 1회 + 설정 토글 켜면 시작 시마다 | 설치된 각 엔진의 `%LOCALAPPDATA%\UnrealEngine\<버전>\Saved\Config\WindowsEditor\EditorSettings.ini`의 최근 프로젝트 목록을 읽어 추가 |

- 같은 `.uproject` 경로는 대소문자 무시하고 중복 제거한다.
- **감지되면 무조건 목록에 표시한다.** 사용자가 목록에서 숨기거나 제거하는 기능, 무시 목록은 없다.
- **목록은 디스크 상태를 그대로 반영한다.** `.uproject` 파일이 삭제·이동되어 더 이상 존재하지 않으면 해당 항목은 목록에서 자동으로 사라진다 (시작 시 검사 + 파일 감시 이벤트). 이동된 프로젝트가 감시 폴더 안에 있으면 새 경로로 다시 감지된다.
- 프로젝트가 사라졌다가 같은 경로로 다시 나타나면 즐겨찾기·마지막 연 시간을 복원한다 (경로 기준으로 메타데이터를 보관).

## 8. 핵심 로직 명세

### 8.1 엔진 자동 감지 (Windows)
| 출처 | 위치 | 식별자 |
|---|---|---|
| Launcher | `%ProgramData%\Epic\UnrealEngineLauncher\LauncherInstalled.dat` (JSON, `InstallationList`에서 `AppName`이 `UE_x.y`인 항목) | `"5.9"` 형태 |
| Launcher (보조) | `HKLM\SOFTWARE\EpicGames\Unreal Engine\<버전>` 의 `InstalledDirectory` | `"5.9"` 형태 |
| 소스 빌드 | `HKCU\SOFTWARE\Epic Games\Unreal Engine\Builds` (값 이름 = GUID, 값 = 경로) | `{GUID}` |
| 수동 | Hub 자체 저장소 | 등록 시 생성한 GUID |

- 모든 후보는 `Engine\Build\Build.version`을 읽어 실제 버전을 확인하고, 파일이 없으면 무효 처리한다.
- 경로 정규화 후 같은 폴더는 하나로 합친다 (우선순위: Launcher > 소스 빌드 > 수동).
- 감지는 앱 시작 시 백그라운드에서 1회, 설치 탭의 ⟳ 클릭 시, 그리고 `LauncherInstalled.dat` 파일 변경 감지 시 재실행한다.

### 8.2 프로젝트 정보 읽기
- `.uproject`(JSON)에서 `EngineAssociation`, `Modules`(C++ 여부 판별용 내부 정보) 읽기
- 프로젝트 이름 = 파일명(확장자 제외)
- 유효성 검사(파일 존재, 엔진 매칭)는 시작 시 백그라운드에서 전체 실행, 이후 감시 이벤트로 갱신

### 8.3 EngineAssociation 해석
| 값 | 해석 |
|---|---|
| `"5.9"` | 출처 무관하게 Major.Minor가 같은 엔진 중 Launcher 우선, 없으면 가장 높은 Patch |
| `"{GUID}"` | Builds 레지스트리/수동 엔진의 GUID와 매칭 |
| `""` (빈 값) | 프로젝트 상위 폴더를 따라 올라가며 엔진 루트를 찾음 (엔진 내장 프로젝트) |
| 매칭 실패 | "엔진 없음" 또는 "알 수 없는 빌드" 상태 |

### 8.4 실행 프로세스 추적
- Hub가 실행한 에디터의 PID와 프로젝트를 매핑해 보관하고, 프로세스 종료 이벤트를 비동기로 기다린다 (폴링 금지).
- 앱 재시작 시에는 실행 중인 `UnrealEditor.exe` 프로세스의 커맨드라인에서 `.uproject` 경로를 읽어 상태를 복원한다.

## 10. 데이터 저장

위치: `%APPDATA%\UnrealHub\`

| 파일 | 내용 |
|---|---|
| `settings.json` | 설정 모달의 모든 값, 창 위치·크기, 마지막 탭, 프로젝트 정렬 상태 |
| `projects.json` | 프로젝트 목록 (경로, 즐겨찾기, 마지막 연 시간, 추가 출처) |
| `engines.json` | 수동 등록 엔진 (GUID, 경로), 감지 결과 캐시, 폴더 용량 캐시 |
| `logs\` | 일별 로그 파일, 7일 보관 |

- 쓰기는 임시 파일에 쓴 뒤 교체(atomic write)해 손상을 막는다.
- 파일이 손상되면 백업(`.bak`)에서 복구하고 토스트로 알린다.
- 각 파일에 `version` 필드를 두어 이후 스키마 변경 시 마이그레이션한다.

## 14. 미결 사항

1. **새 프로젝트 생성 방식 검증**: 템플릿 복사·치환 방식이 엔진 버전별로 에디터의 결과와 동일한지. 특히 C++ 이름 치환과 스타터 콘텐츠·하드웨어 타기팅 ini 키의 버전별 차이.
2. **EditorSettings.ini 최근 프로젝트 포맷**: 5.6~5.9 버전별 키 이름·형식 차이 확인 필요.
3. **설치 파일 형식과 코드 서명**: 설치형(MSI/EXE) 도구 선정, SmartScreen 경고를 피하기 위한 서명 인증서 필요 여부.
4. **5.6 미만 엔진 처리**: 감지·열기만 지원하고 새 프로젝트 생성은 5.6 이상으로 제한할지, 아예 5.6 미만은 목록에서 숨길지.
5. **다국어 기본 문구**: 한국어/영어 문자열 관리 방식(Fluent 등).
6. **macOS/Linux 확장 시점**: `platform` 크레이트 경계만 지켜두고 일정은 미정.
